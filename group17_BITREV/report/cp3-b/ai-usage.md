## 二、使用時機、具體用途與提示詞摘要

依作業規範，AI 工具僅作為「輔助思考與查核」用途，具體使用場景如下：

### 1. R-type 欄位與機器碼位移公式推導
- **時機**：撰寫 `encoding.md` 時。
- **用途**：確認 RISC-V R-type 指令格式中各欄位的位移量（Shift amounts）：
  $$\text{機器碼} = (\text{funct7} \ll 25) \mid (\text{rs2} \ll 20) \mid (\text{rs1} \ll 15) \mid (\text{funct3} \ll 12) \mid (\text{rd} \ll 7) \mid \text{opcode}$$
- **組員查核**：手動對照 RISC-V 手冊（Volume I, Unprivileged ISA, §2.2），確認 `opcode[6:0]`、`rd[11:7]`、`funct3[14:12]`、`rs1[19:15]`、`rs2[24:20]`、`funct7[31:25]` 之位元範圍完全無誤。

### 2. 機器碼手算推導過程核算
- **時機**：計算 3 個範例（含邊界值）的 16 進位數值時。
- **用途**：檢查二進位至十六進位的中間移位數值，避免手動相乘時出現筆誤。
- **關鍵查錯**：AI 初稿在部分位移項目的十六進位展示出現筆誤（例如誤寫成未對齊的乘數），組員發現後以嚴謹數學算式校正：
  - 範例 1：`10 << 15 = 327680 = 0x50000`、`10 << 7 = 1280 = 0x500`，總和得 `0x0005050B`。
  - 範例 2：`11 << 15 = 360448 = 0x58000`、`5 << 7 = 640 = 0x280`，總和得 `0x0005828B`。
  - 範例 3：`18 << 15 = 589824 = 0x90000`、`9 << 7 = 1152 = 0x480`，總和得 `0x0009048B`。

### 3. Matplotlib 欄位分佈圖視覺化繪製
- **時機**：生成 `cp3_encoding_fields.png` 欄位圖時。
- **用途**：透過 Python Matplotlib 腳本自動生成包含 3 個範例的 32-bit 位元方塊圖。
- **組員校正**：依據小組審查意見，手動翻轉座標軸為 `ax.set_xlim(32, 0)`，以符合硬體規格書習慣（左側為 MSB bit 31，右側為 LSB bit 0）；並調整 `funct7` 方塊文字寬度與色彩標籤，確保 `funct7=0000000` 完整展示不被裁切。

### 4. Git 歷史與團隊協作衝突解決
- **時機**：在推送 PR 時面對團隊 `main` 分支前進所產生的非快轉（non-fast-forward）衝突。
- **用途**：輔助分析 Git commit 歷程圖，指引精確的 `git rebase --onto` 與 `git commit --amend` 流程。
- **組員決策**：主動還原 `report/CP3.md`，將給組員 D 的段落改放於 `cp3-b/README.md`，堅持不跨界修改其他組員負責之檔案。

## 四、學習成效展示與費曼反思（依 §7.4 規定）

### 1. 費曼白話說明（200 字以內，用自己的話解釋）
> `bitrev`（位元反轉）指令就像將一條有 32 格刻度的木尺從正中央折轉倒置。最右邊第 0 格的數值直接送到最左邊第 31 格，數值 `1`（`...0001`₂）反轉後即變成高位帶 1 的 `0x80000000`。
> 在硬體電路中，它完全不需要任何邏輯閘（AND/OR/XOR）或 ALU 運算器，只要將輸入端 32 條導線在電路板上交叉連接至輸出端即可完成，既無閘延遲亦不佔矽晶面積。

### 2. 5 Whys 推理鏈（關鍵設計決策）
1. **為什麼 BITREV 指令不需要 ALU 運算？**
   - 因為它沒有對位元進行組合、相加、遮罩等數學運算，純粹是一對一的位置互換（$rd[i] = rs1[31 - i]$）。
2. **為什麼位元互換不需要邏輯閘？**
   - 因為每個位元的真值表是 $0 \to 0$、$1 \to 1$（恆等函數），物理上只要一條導線就能傳遞。
3. **為什麼接線可以完全固定，連多工器（MUX）都不需要？**
   - 因為對應關係 $i \to 31 - i$ 是固定常數，不取決於輸入值，亦無像循環移位（ROTL）需要第二個運算元決定位移量。
4. **既然硬體這麼簡單，為什麼軟體 RV32IM baseline 要 36 條指令？**
   - 因為 RV32IM 沒有任意重排位元的硬體指令，軟體必須採用 16/8/4/2/1 五階分治遮罩與左右位移反覆拼接，產生 36 條靜態指令的開銷。
5. **為什麼將 BITREV 納入 custom-0 自訂指令具備極高價值？**
   - 因為硬體只需增加 32 條交叉導線與解碼器對 `custom-0`、`funct7=0000000` 的判斷，就能將 36 個指令週期的運算在 1 個週期內完成，減少 **97.2%** 的指令負擔。
