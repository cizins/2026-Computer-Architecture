# CP1 — C baseline

## 1. 本次目標

本次 CP1 的目標是使用 C 語言實作 32-bit BITREV 基準函式，
將輸入值的位元順序完全反轉，並設計至少 10 組測資驗證函式正確性。

BITREV 的定義為：

```text
rd[i] = rs1[31 - i],  i = 0 … 31
```

## 2. 設計內容

本組使用以下函式介面：

```c
uint32_t bitrev(uint32_t x);
```

核心函式位於 `src/c_baseline/bitrev.c`，宣告位於
`src/c_baseline/bitrev.h`。

實作採用分治式位元交換法，依序交換 16-bit、8-bit、4-bit、
2-bit 區塊，最後交換相鄰的單一位元。每個階段使用遮罩保留
正確的位元，再透過位移完成交換，因此總共只需要 5 個步驟，
不需要迴圈。

測試程式另外使用 naive 逐位元方法作為獨立參考實作，
用來交叉確認 `bitrev()` 和測資預期值。

## 3. 結果與分析

本次共設計 11 組測資，涵蓋零值、全 1、最低位元、最高位元、
對稱圖樣、一般測試值及隨機值。

| # | 輸入 (hex) | 預期輸出 (hex) | 備註 |
|---|---|---|---|
| 1 | `0x00000001` | `0x80000000` | 邊界：LSB 反轉至 MSB |
| 2 | `0x0000000F` | `0xF0000000` | 低 nibble 反轉至高 nibble |
| 3 | `0x12345678` | `0x1E6A2C48` | 題目指定範例 |
| 4 | `0x00000000` | `0x00000000` | 邊界：全零 |
| 5 | `0xFFFFFFFF` | `0xFFFFFFFF` | 邊界：全一，自我反轉 |
| 6 | `0x80000000` | `0x00000001` | 邊界：MSB 反轉至 LSB |
| 7 | `0x0000FFFF` | `0xFFFF0000` | 交換左右兩個 16-bit 區塊 |
| 8 | `0x00FF00FF` | `0xFF00FF00` | 交錯 byte 圖樣 |
| 9 | `0xAAAA5555` | `0xAAAA5555` | 對稱位元圖樣 |
| 10 | `0xDEADBEEF` | `0xF77DB57B` | 隨機測試值 |
| 11 | `0xF0F0F0F0` | `0x0F0F0F0F` | nibble 圖樣 |

使用 `make run` 執行測試後，結果如下：

```text
BITREV CP1 test suite (11 vectors)
11/11 passed, 0 failed
```

所有測資的 `bitrev()` 實際輸出、預期輸出，以及 naive
逐位元參考實作輸出都相同，因此本次測試全部通過。

本函式只進行位元重新排列，不會發生算術溢位。BITREV 具有以下
對稱性：

```text
BITREV(BITREV(x)) = x
```

因此全零、全一及對稱圖樣在反轉後會維持原值。

## 4. 遭遇的問題與解法

問題：
一開始容易將「byte 反轉」誤認為「bit 反轉」。例如只交換
`0x12345678` 的 byte 順序，只會得到 `0x78563412`，
但這不是完整的 BITREV 結果。

解法：
將 32-bit 位元反轉拆成五個階段：先交換 16-bit、8-bit、
4-bit、2-bit，最後交換相鄰的單一位元。每個階段都使用遮罩
保留正確的位元，再透過位移完成交換。

另外，為了避免只測到核心函式本身的錯誤，測試程式加入獨立的
naive 逐位元參考實作，並同時比較實際輸出、預期輸出與參考輸出。

## 5. 白話說明

BITREV 就像把一排 32 顆燈泡從左到右重新排列成由右到左。
最左邊的燈會跑到最右邊，第二顆會跑到倒數第二個位置，
依此類推。程式不是一顆一顆慢慢搬，而是先交換大區塊，
再交換較小區塊，最後交換相鄰位元，因此可以快速完成反轉。
